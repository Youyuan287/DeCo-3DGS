# METHOD_FAILURE_ANALYSIS

**前置条件说明**：T1–T4 全部通过（表示层的实现是正确的：观测导出忠实、K=1 与生产聚合等价、分组非伪、评分数学无错）；T5 因服务器无 GPU 而 **BLOCKED**。因此本文的定位是：

> **本文不主张「多证据算法本质无效」。** 本文只指出：在当前这个已确认损坏的读出规则内部，多证据表示没有产生任何可观测增益；并给出 7 条结构假设中**已被数据支持**与**已被数据否定**的部分。

凡未标「已实测」的，均为**假设**。

## 0. 一个必须先说清的事实

`k1 / b2 / b3` 三臂在**完全相同的**（损坏的）读出规则下得到

```
0.006673 / 0.006540 / 0.005722
```

即多证据带来的变化是 **−0.0001 / −0.0010**，而这三臂的特征差异是 `pearson(k1,b2)=0.89456`、`pearson(k1,b3)=0.88078`，top-5 集合几乎重合。**在能观测到的分辨率上，多证据 ≈ 单证据。**

这不代表算法无价值；它代表**当前这个实验设计无法测量它的价值**（数值全被读出规则压到 0.006 附近的地板上）。

## 1. 逐条核对任务书列出的 7 个结构假设

### H1 残差空间把可靠视角过度拆分，产生不稳定证据组 — **部分成立（已实测）**

- 残差空间 `h = l2n(nf − (nf·u)u)`，`u` 与生产场景均值方向 `cos = 0.990734`。
- 实测：删掉 `u` 之前，`var(f·m̂) = 0.001844`，随机方向为 `0.001947` —— **共享方向几乎是常数偏移，不主导排序**。因此「去偏」在**方差**意义上拿掉的很少，却把剩下的信号压进一个更小的动态范围里再做最远优先切分。
- 后果实测：`group_count {1:67, 2:120, 3:113}`，组内两两 cos **0.7540**，`cos(group, base)` **0.9030**。组是「被切开的均值」，不是「不同的语义」。
- **判定：成立，但不是主要矛盾** —— 因为组虽碎，打分时几乎不用它们（见 H6）。

### H2 固定 K 强制拆成不必要的多个模式 — **成立（已实测）**

- `EvidenceConfig.max_evidence=3` 是**上界**，实际切几组由**观测散布的几何**决定，与「这个区域有几种语义」无关。
- 实测平均 2.15 组/区；67 个区只有 1 组，113 个区顶到 3 组。
- 更关键：`min_group_weight=0.05` 会把质量 < 5 % 的组**丢弃**。实测 K=3 区第三组的平均 prior 仅 **0.0561**（见 `region 236`），正好卡在阈值上 → **少数但可能重要的视角被系统性抹掉**，这与「用多证据保留少数视角语义」的初衷相反。

### H3 代表性观测选择偏向单个异常视角 — **否定（已实测）**

- 播种用加权 medoid（`argmax(sim @ a)`），不是单点 argmax；组值是组内加权平均，不是单条观测。
- 实测每组都是 `a[mask]` 归一化后的加权平均，无「只留一条观测」的情况。

### H4 证据支持权重使少数重要证据无法影响查询 — **成立（已实测）**

- `score = Σ_k softmax_k(raw_k/0.08 + log prior_k) · raw_k`，实测 mean max-weight **0.7211**、mean 熵 **0.6344**（均匀为 0.767）。
- 即：**约 72 % 的权重给了单一组**，`prior`（证据支持度）只在 log 域里加了一个很小的偏置。少数证据被压到 0.05–0.17 的权重，实际无法改变排序。

### H5 softmax 温度导致退化为均匀加权 — **否定（已实测）**

- 熵 0.6344 < 均匀 0.767，最大权重 0.7211 > 0.464。**没有退化为均匀**，反而偏向近硬 max（但未退化，`max-prob > 0.99` 的比例为 0.000）。

### H6 多证据查询过度偏向某个偶然高相似度证据 — **成立，且是核心（已实测）**

- `score ≈ 0.72·max_k + 0.28·其余`，即**近似 max over K**。
- `E[max_k cos]` 随 K 单调增：实测 K=1 区 0.0164 vs K=3 区 0.0172（随机方向，+0.0008）；在真实 prompt `bowl` 上 top-5 分数 k1 0.3119 → b2 0.3186 → b3 0.3223（**+3 %**）。
- 在 67 个 K=1 区与 113 个 K=3 区混排的候选池里，这等价于**给"切得碎"的区域无条件加分**，与语义无关。
- 更要命的是：由于组值是原始特征的子集均值，`max_k` 与「该区某个视角恰好与 prompt 对齐」高度相关 —— 这正是「偶然高相似度证据」的定义。

### H7 缺失三维局部支持，把对象级证据赋给所有子区域 — **成立（结构上明显，未做消融）**

- 证据组只在**单一区域内部**构建，没有任何邻域/父子约束。
- ramen 的 level-3 区中位 187、最大 **27 252** 个 gaussian（整个房间级别）。区域越大，其观测集合越杂，切出的组越接近「视角聚类」而非「语义聚类」。
- 同时 `level-2` 下探（认证路径有）被新评测器删掉 → **大区无法被细化为小区**，只能整块被选中。这与 T4-B 实测的「raw 余弦平均多选 16 % gaussian 质量、`hand` 多 10×」是同一条因果链。

## 2. 核心设计缺陷（回答 C）

> **多证据没有改变打分所用的向量。**

拆开说，三个事实叠加：

1. **组值是同一批观测的凸组合**：`p_k = Σ_i a_i f_i / ‖·‖`，`p_k ∈ cone({f_i})`。任何 `Σ_k w_k p_k` 也仍在该锥内。对线性相似度打分（`p·t`）而言，**多证据至多是"换了一组权重"，没有引入锥外的新信息**；而生产特征 `base = l2n(Σ a_i f_i)` 本来就是这个锥里最自然的代表点。
2. **唯一能跳出锥的载体被丢弃**：去偏残差 `d_k = l2n(Σ a_i h_i)` 才是「不同于场景共性的那部分语义」，它被算出来、存进 npz、然后**没有任何评分函数读它**（`multi_evidence.py:102` 写，`:114-173` 只读 `features`）。
3. **读端还把权重结构压平了**：`T=0.08` 使 `score ≈ max_k`，而 `alpha=0.0` 又关掉了 `score_bank_certified_style` 里的场景中心去除。于是「残差 + 多证据 + 查询加权」这条设计链，在评测时**三段全断**。

**因此，即使用认证读出、即使 NAG 一致，只要第 2 点不改，`K>1` 相对 `K=1` 的期望增益也应接近 0。** 这与当前实测（0.0065 vs 0.0067）一致，也与 `pearson(k1,b2)=0.89` 一致。

一句话版本：**这不是"多视角语义证据保留"，而是"把同一个均值用三种方式重新加权"。**

## 3. 如果要在正确读水下检验它，最小的可证伪预测

（这些是**预测**，不是结论；每条都能被一次 GPU 实验证伪，不需要扫参。）

- **P-1**：把读出换成认证路径（`compute_similarity` + `search_matched_superpoint_in_mhtree`），`K=1` 与 `K=3` 的 mIoU 差异应 < 1 pt。若 > 3 pt，则我上面「凸组合」的推理有漏。
- **P-2**：若把打分向量换成残差 `residuals`（而不是 `features`），`K=3` 应有可测变化 —— 因为这是唯一真正用了新信息的路径；但它很可能**变差**，因为残差丢掉了区域的主体语义（`cos(group,base)=0.903` → 残差只占 10 % 能量）。
- **P-3**：组数应由语义而非几何决定；在当前 `max_evidence=3` + 观测散布切分下，`group_count` 与区域的**语义数**（用 GT 类别数近似）相关性应接近 0。这一条**不需要 GPU**（只需 GT 类别 + 已算出的 group_count），是下一步最便宜的检验。

## 4. 不建议做的事

- 不建议再跑 `min_group_weight` / `temperature` / `max_evidence` 的扫描。原因已由 H5/H6 给出：**温度不是瓶颈**（未退化），`max_evidence` 只是上界，`min_group_weight` 只影响 5 % 质量的组。调这三个参数不会跳出「凸组合」这个结构性上限。
- 不建议再在 ramen 上做新模块。当前 0.0067 的读数无法区分任何方法的好坏，先把读出修好才有测量能力。
