## T2 单向量等价性 — PASS（本次审计补做的真检查）

**断言**：K=1 且不去偏时，新模块应复现同输入的原始加权聚合。

**注意**：原脚本的 `k1_max_abs_error = 0.0` **不能**作为证据 —— 它是 `analyze_ramen_observations.py:22-30` 用**同一个** `l2n`、**同一套**权重、**同一个**循环顺序自洽重算。必须与**生产已保存的** `nag_feat[2]` 比，并且必须包含 ROFA。

**参考实现（独立，numpy）**：
```
x_i  = l2n(f_i) * w_i                      # 生产 merge_proj.py:215
对每个区域取 {x_i}，在 l2n(x_i) 上算 ROFA(tau=3)：
    mean_sim = (cos_sim.sum(1)-1)/(n-1);  mu,sigma = mean_sim.mean(), mean_sim.std()
    keep = mean_sim > mu - 3*sigma;  空集则保留 argmax
prod_hat = l2n(mean(kept))
```
与 `work/multievidence/ramen/sai_nag_3.0.pt` 的 `nag_feat[2]` 逐区域比对：

| 对比 | cos 均值 | cos 最小 | >0.9999 区数 | <0.9 区数 |
|------|----------|----------|--------------|-----------|
| **prod_hat vs nag_feat[2]** | **0.999591** | 0.938409 | **296 / 300** | **0** |
| k1 bank vs nag_feat[2] | 0.998997 | 0.919666 | 272 / 300 | 0 |
| k1 bank vs prod_hat | 0.999406 | 0.919666 | 276 / 300 | 0 |

**ROFA 影响量**：tau=3 下每个多观测区域平均保留 40.69 / 41.1 条（保留率 0.991）→ ROFA 在本场景只剔除 **0.9 %** 观测，这正是 k1（ROFA 前）与 prod（ROFA 后）cos 仍达 0.998997 的原因。

**断言通过**：`K=1` 与生产加权聚合在数值上等价（差异仅为 ROFA 的 0.9 % 观测）。
**同时排除**：权重平方乘入、归一化顺序错误、观测丢失、区域错配（否则 cos 会显著掉）。

**样本**：全部 300 个有观测的 level-3 区域（非抽样，直接全量统计）。

| 检查 | 实测 | 判定 |

| `cos(group, base)` 均值 | 0.9030 | 各组贴近区域均值，但不等同 |
| 每条观测是否被重复分配 | 否 —— `assign = argmax(sim[:,chosen])`，硬分配 | PASS |
| 观测是否丢失 | 否 —— `idx` 覆盖该区全部 `w>0` 观测；组质量之和 = 1 | PASS |
| 模式内权重归一化 | `a = w/Σw`，组内再用 `a[mask]`，Σ = 组质量 ≤ 1 | PASS |
| 是否对已归一化特征二次加权 | `ff = l2n(f)`，之后只乘 `a`（一次） | PASS |
| 空证据槽是否被当有效 | `valid[z,k]` 布尔掩码；打分时置 `-1e9` | PASS |
| K=1 是否严格退化 | 是（T2 已证 cos 0.998997） | PASS |
| K>1 是否保留不同语义 | 是，但**只体现在分组**，不体现在打分（见下） | 部分 |

**关键否定结论**：`build_bank` 的组值取的是 **原始特征** 的加权平均

```python
p = l2n((a[mask,None] * ff[mask]).sum(0))   # ff = 原始特征
d = l2n((a[mask,None] * hh[mask]).sum(0))   # hh = 去偏残差, 只写进 resid
```

`residuals` 被保存进 npz 后**没有任何打分函数读取**（`score_bank:114-135` 与 `score_bank_certified_style:153-173` 都只读 `bank.features`）。
→ 110 / 300 个区域在 raw 与 debiased 两种模式下组数不同，但**被打分的向量不变**，这就是 b2 ≈ b3 的原因。

## T5 真实评测接入 — BLOCKED（无 GPU）

**断言**：新方法与原始 ReLaGS 使用完全相同的「区域 → 渲染像素」映射与评测逻辑。

| 检查项 | 结果 |
|--------|------|
| `labels = nag["nag"][-1]`，长度 372 270 = gaussian 数 | PASS |
| `rel = isin(labels, chosen)` → `_semantics = rel.expand(-1,20)` | 与 `eval_lerf_relags.py:90-92` 逐行等价 |
| `sem = render(cam, gaussians, pipe, bg)["semantics"]`；`pred = sem > 0.5` | 与 `eval_lerf_relags.py:93-94` 等价 |
| 相机：`{c.image_name: c for c in scene.getTrainCameras()}`，键 = GT jpg 词干 | 与 `:69` 等价 |
| 分辨率：`cam.image_height/width` = GT 尺寸 731×988 | PASS |
| GT：`cv2.fillPoly` 联合 `category==prompt` | 与 `:96-99` 等价 |
| IoU：`inter/union`，`union==0 → nan`（71 条无 nan） | 与 `:100-102` 等价 |
| mIoU：先每图均值再跨图均值 | 与 `:113-117` 等价 |
| **`filter_small=50`** | **缺失** |
| **`remove_small`（相似度间隙截断）** | **缺失** |
| **`level_until=3` 的 level-2 下探** | **缺失** |
| **NAG 文件与认证路径同一份** | **否（304 vs 249 vs 未知）** |
| 实际重跑一次渲染验证 | **无法**（无 GPU） |

**判定 BLOCKED**。可以确认的是：**渲染段与 GT/IoU 段代码等价**；不能确认的是「在同一份 NAG、同一套候选规则下数值可复现」。

**因此**：按任务书「T1–T5 全部通过才允许判断多证据算法本身效果不佳」的门槛，**当前不允许下"算法无效"的结论**。但可以下一个**不需要 T5** 的结论：在**同一个（已损坏的）读出规则**内部，k1 / b2 / b3 的 mIoU 为 0.00667 / 0.00654 / 0.00572，彼此差 < 0.001 —— **多证据表示在本实验中没有产生可观测增益**，这一条是同一读出下的对照，成立。
