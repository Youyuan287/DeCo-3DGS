# LERF 候选生成探针报告（level-1 细粒度提案，探索性）

日期：2026-10-30
性质：探索性探针（非方法结论）；预注册门控不适用，仅用于判断是否值得投入完整候选生成阶段。
范围：29 条召回失败查询（池内无正确对象，oracle best ≈ 0.03）。

## 1. 背景与假设

NAG 层级：4 层标签（聚类数 7852/1853/507/249），特征只存后三层；level-1（1853 簇，中位 36 高斯）是可用最细粒度。假设：小目标（corn、onion segments、door handle）在 level-2 被合并进大簇，但在 level-1 是独立簇。

## 2. 探针结果（29 条召回失败查询，逐候选渲染取最大 IoU）

| 提案 | 平均 oracle best | 候选数均值 | best≥0.3 | best≥0.1 |
|---|---:|---:|---:|---:|
| level-2 top-5（released） | 0.027 | 5.7 | 0 | 3 |
| level-1 top-5 | 0.025 | 7.4 | 0 | 3 |
| **level-1 top-10** | **0.075** | 16.0 | **2** | **6** |

- level-1 top-10 相对 released：**9 条提升、5 条变差**（变差是因为 level-1 深池不包含 level-2 候选；取并集则不会变差）。
- 逐场景：figurines 0.044→0.119（2 条大幅提升）、waldo 0.065→0.316（1 条 +0.25）、ramen 0.020→0.022、teatime 0.001→0.001。
- 典型修复案例：figurines / waldo 的 tesla door handle（0 → 0.068 / 0.305）。

## 3. 收益量化（为什么建议停止）

- 即使采用"并集提案 + 完美选择器"，召回族 oracle 也只从 0.027 提到约 0.075–0.08；折算到全部 208 查询的场景均值上限约 **+0.5～1.0 点**。
- 且并集带来两个新的工程问题：level-1 与 level-2 的相似度分数不在同一特征空间，直接合并排序没有依据；选择器（IoU 回归/剪枝）需要在混合分布上重新训练并验证，存在分布偏移风险。
- 对比：当前方法 C 已通过预注册门控拿到 +2.40；候选生成阶段的预期上限（+0.5～1）和风险（重训、混合打分）不成比例。

## 4. 建议

- **不建议**投入完整的混合提案 + 选择器重训阶段（半天到一天，预期 ≤+1 点）。
- 若仍要做，最小可行版本是：并集提案（level-2 top-5 ∪ level-1 top-10）→ 用统一的 root 级相似度重打分 → 复用 C 的剪枝/并入 → 预注册门控；但这一步需要先解决跨层分数可比性问题。
- 论文层面：把"13.9% 查询池内无正确对象；level-1 细粒度只能挽回 3/29 条"写入 limitation 与 future work，支撑"瓶颈在候选生成"的结论。
