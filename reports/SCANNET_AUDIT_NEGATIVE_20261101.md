# ScanNet-10 上的判决审计：负结果与作用域说明（2026-11-01）

目的：把 LERF 的审计器（配对证词证书）移植到 ScanNet-10，检验跨数据集可用性。
结论：**不迁移**。C1/C2 off 臂 40.36 → 最好 36.73；C1+C2 主链 50.18 → 最好 45.91。
原因不是阈值，也不是"跑错臂"，而是作用层不同 + 配对前提不成立；
把任务重构成同 query 的集合选择（配对前提成立）后仍 −0.9；换独立 SAM 证人也无增益
（保守证书弃权、无损）。瓶颈是**场的实例粒度**：root 是区域，不是物体。

---

## 1. 设置

- 数据：`scannet_v2_certified_20261029` 10 场景；观测 `export/observations_level3.npz`
  （逐视角 token、权重、view_id）；模型 `/root/verify58_20261029/full10/<scene>/model/sai_nag_3.0.pt`。
- 任务：19 类闭集 per-root 分类；GT 为每高斯类别（最近 GT 点）。
- **现任**：released 标签（root 3D 特征 `x @ t` 的 argmax）。
- **证人**：该 root 的逐视角观测 token；逐视角判决 $s_o(c)=\langle F_o,t_c\rangle$。
- **证书**：$\delta_o(c)=s_o(c)-s_o(L_0)$，$z_c=\bar\delta/(\sigma_\delta/\sqrt{n/2})$；
  改判到 $\arg\max_c z_c$，要求超过阈值。
- 变体：
  - `audit`（多数，$z>0$）；`audit95`（$z>1.64$）；
  - `cal/cal95`：先按场景内每类平均分数中心化（去类先验），再做同样证书；
  - `rank`：逐视角序数判决（rank 差）；
  - 对照：`no_cert`（直接按平均边际改判）、`vote`（逐视角 argmax 多数票）。

### 2.1 在 C1+C2 主链（on 臂，macro 50.18）上复核

上面的实验跑在 C1/C2 off 臂（40.36）。为排除"跑错臂"的解释，用
`ablation/v2_on_on/<scene>/predictions_and_scores.npz` 的 `scores_off`
（C1+C2 on、V2 off，即 50.18 主链）作为现任，逐视角证人不变，重跑同一审计：

| 变体 | 10 场景 macro | 改判（合计/约 1951 roots） |
|---|---:|---:|
| **baseline（C1+C2，V2 off）** | **0.5018** | — |
| audit（多数证书） | 0.0207 | ~1600（82%） |
| audit95（保守） | 0.0529 | ~1300 |
| cal majority（类先验中心化） | 0.0506 | ~1580 |
| **cal95（中心化 + 保守）** | **0.4591** | ~250（13%） |

逐场景 baseline/cal95：0.5128/0.4043、0.8250/0.8180、0.3578/0.3462、0.4338/0.4016、
0.5198/0.4516、0.4977/0.4976、0.4347/0.3675、0.4454/0.4454、0.5217/0.4450、0.4692/0.4138。

**结论**：换成 50.18 的主链后仍然失败（最好 45.91，−4.3）。
在 cal95 不触发或只触发 2–3 次的场景（scene0200/scene0400），结果与 baseline 完全相同；
一旦触发 30–40 次，就掉 4–7 分。即"不改就不伤，改就错"。

### 2.2 恢复同 query 结构（query 级审计）仍然失败

per-root 失败的一个解释是"比较了两个不同类，配对前提不成立"。为排除这个解释，
把闭集重构成**同一 query 的集合选择**：对每个类别查询 c，
现任 = released argmax 分配给 c 的 root 集合 I_c；
挑战者 = 按逐视角证据（top-3 平均）排序、取同样大小的 root 集合 S'_c；
证书比较两个集合同一批视角的支持度（类先验对两边相同，自然抵消）。
官方评测口径（GT 不在 19 类内的高斯 ignore）下 baseline 逐位一致。

| 变体 | 10 场景 macro | 说明 |
|---|---:|---|
| **baseline（released 集合）** | **0.5018** | 与分类臂一致 |
| always-challenger | 0.4229 | 无证书直接换集合 |
| audit（多数证书） | 0.4666 | |
| audit95（p≥0.95） | 0.4926 | 27/96 个类别查询触发 |

逐场景（baseline → audit95）：0.5128→0.5201、0.8250→0.8251、0.3578→**0.4505**、
0.4338→**0.4947**、0.5198→0.4924、0.4977→0.4427、0.4347→0.3561、0.4454→0.4280、
0.5217→**0.5349**、0.4692→0.3817。

**结论**：配对前提修好后仍然整体 −0.9（三胜五负两平）。问题从"前提"转到"证人质量"：
逐视角区域 token 的排序在一些场景明显优于 released（scene0070 +9.3、scene0097 +6.1），
在另一些场景明显更差（scene0645 −8.7、scene0347 −7.9），而证书无法分辨这两种情况。
审计器需要的是"配对优势与正确性相关"的证人，ScanNet 的区域 token 不满足；
LERF 的 2D mask-CLIP 证据满足。

### 2.4 SAM 证人 pilot（独立 2D 分割）

假设："区域 token 弱是因为证人来自场自身；换独立 SAM mask 会变好。"
实现（`analysis/scannet_sam_pilot.py`）：root 高斯 → 相机投影（整场深度挡剔）→
mask bbox 作 SAM box prompt → 选与投影 mask IoU 最大的分割 → 掩膜图 CLIP → 19 类证据；
challenger 改按 SAM 证据排序。做 scene0645（token 最差）与 scene0070（token 最好）两个场景。

| 量 | scene0645（token 最差） | scene0070（token 最好） |
|---|---:|---:|
| baseline | 0.4692 | 0.3578 |
| 有 SAM 证据的 root | 112 | 56 |
| always-SAM challenger | 0.0240 | 0.0127 |
| 审计（多数证书） | 0.3234（4 次触发） | 0.2641（3 次） |
| 审计（保守证书） | 0.4692（0 次，=baseline） | 0.3587（1 次，+0.0009） |

诊断图（`analysis/results/20261101/sam_debug2/`）：投影后的 root 常常是**跨墙 + 床的粗区域**，
SAM 圈到的是物体（床头板/床）——两者粒度不匹配。不是 SAM 不好，是 ScanNet 的 root 不是物体。

**结论**：瓶颈是**场的实例粒度**，不是证人来源。对照场景（token 证人最好的 0070）同样失败，
排除"选错了场景"。保守证书在证人不可靠时正确地弃权（几乎无损），但也就没有收益。要把 ScanNet 救活，需要 object-level 候选（SAM mask → 3D 实例）——
这是一条更大的方法路线（与之前 part/实例生成方向重合），不是换证人能解决的。

## 3. 为什么失败（与 LERF 的差别）

1. **配对前提不成立**。LERF 的现任与挑战者是**同一个 query 的两个答案**（同一文本，
   不同候选集），任何与 query 有关的公共偏置在配对差分中抵消。
   ScanNet 是**两个不同类**的比较：类的相似度尺度（类先验）与视角无关，
   $\delta_o$ 里它是一个常数，配对消不掉。`cal` 变体正是把它显式减掉，
   于是从 0.009 回到 0.046，`cal95` 回到 0.367——但仍不到 baseline。
2. **逐视角判决的类别判别力不足**。去掉类先验后剩下的视角间差异主要是噪声
   （区域混合 token），证书再保守也只是"少改"，不能"改对"。
   这与已有的 late-interaction 负迁移结论一致（top3 22.85 vs baseline 40.36）。
3. **released root 特征已经校准良好**。闭集 argmax 依赖绝对分数刻度；
   逐视角证据只保留"最像某类"的视角，破坏刻度。审计器只能改判、不能重新校准。

### 3.1 为什么 C1/C2 有效而审计失败（两者在不同层）

| | C1 + C2 | 判决审计 |
|---|---|---|
| 作用层 | **全局分数场**：同一变换作用于所有 root、所有类 | **逐 root 决策**：覆盖个别标签 |
| 修复对象 | 系统性标定（均值偏移、文本库构造） | 个别错误决策 |
| 是否改分数 | 是（所有分数一起变） | 否（只改选择） |
| 依赖 | 不需要验证器，靠指标整体验证 | 需要一个可靠且同 query 的验证器 |
| ScanNet macro | 40.36 → 50.18 | 50.18 → 45.91（最好变体） |

两点补充：

- **工作点完全不同**。V2 在 on 臂上只改变 3–6% 的 root、修正幅度中位数 0.0012，
  换来 +0.12 macro；审计器一触发就是 13–82%，所以必然崩。
  在 cal95 只触发 2–3 次的两个场景上，结果与 baseline 逐位相同——"不改就不伤，改就错"。
- **为什么触发率控制不住**。证书用的是标准化边际 $z=\bar\delta/(\sigma/\sqrt{n/2})$；
  每个 root 有 30–100 个视角，标准误很小，任何系统性偏置都会"显著"。
  在 LERF 里这个偏置由配对消掉（同一 query 的两个答案）；ScanNet 的类先验消不掉。
  这不是调大阈值能解决的：cal95 已经把触发压到 13%，仍然 −4.3。

## 4. 对论文的意义（重要，不是失败而是边界）

- 证书的**前提必须写进方法假设**：
  > the certificate compares two answers to the same query; it does not compare two
  > different queries or classes.
  LERF 满足；ScanNet 闭集不满足。
- 方法作用域因此更清晰：**同一 query 下的决策修正**（候选集替换/扩充），
  不是通用分类器后处理。
- 可以作为 limitations 的一句话与一个补充实验：在**没有 query 结构**的任务上，
  审计器应当（也只能）保持现任；实测它无法可靠判断，说明证书的正确性依赖配对。
- 若要在 ScanNet 上做开放词汇，需要 query+实例协议（ScanNet200/OV、逐视角 mask、
  实例级 mIoU），与当前闭集 per-root 协议不可比；本次不做。
