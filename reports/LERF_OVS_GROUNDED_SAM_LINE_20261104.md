# LERF-OVS：Grounded-SAM 重观测主线（完整记录，2026-11-04）

性质：一条**已收口**的探索线。结论为否定，但过程与方法可复用。
所有数字都是本仓库在 fj01 上实测；错过的口径错误也保留在文中。

---

## 0. 一句话结论

**用文本条件检测器（Grounding DINO）+ SAM 重新观测，在 2D 掩膜上确实有效（0.803→0.878，阈值为全样本中位数，属样本内），
但提升到三维后任何阈值都掉分（0.6401→最好 0.6222）。互补性真实存在（逐条 oracle 0.7123），
但四种独立触发信号全部在随机水平（AUC 0.43–0.61），无法定位该互补。这条线关闭。**

---

## 0.5 口径边界（必读，2026-11-05 补）

**Grounded-SAM 在本线中从未构建 3D 高斯语义场。** 它不是"另一种语义场"，也不是"1 bit 版语义场"——
它是**逐 query 的 2D 检测器**，产出掩膜后投影到**已有的** ReLaGS 高斯上，替换读端的那一个逐高斯指示量 `rel`。

两条线的真实关系：

| | 决策发生在 | 产出可复用的场 | query 进入点 |
|---|---|---|---|
| CLIP 读端 | 3D 簇空间（512 维、跨视角聚合） | **是**（`sai_nag.pt`，query-free） | 最后一步点积 |
| GSAM 读端 | 2D 图像空间（单视角、框 + SAM） | **否** | 生成掩膜之前 |

渲染步是复用基线自己的：`eval_lerf_ovs.py:234-236` 与 `lerf_ovs_gsam_e2e.py:136-139` 逐行同构
（`expand(-1,20)` → `render` → `>0.5`）。这是刻意的单变量控制，不是 GSAM 自建的提升器。

**所有 GSAM 数字的合法解释范围只有一句**：把"选哪些高斯"这个决策从 3D 簇空间搬到 2D 图像空间，
2D 更稳、3D 更差。它们**不能**被引用为"一个 3D 开放词汇方法失败了"，也**不能**被引用为
"GSAM 语义场的上限"——后者需要多视角 grounding + 3D 一致性融合（§10.2 条件 2），本线未执行。

两臂也**不是对称比较**：GSAM 在生成掩膜之前就拿到了 query，CLIP 只在最后点积时见到它。
因此 §3/§4 的对比是"两个信息预算"的对比，不是"两个方法在同一任务上"的对比。

## 1. 要回答的问题

现有 ReLaGS/DeCo 读端在 LERF-OVS 上：CLIP 打分 → 选簇 → 渲染。已知有相当比例的查询选错，
且"余弦太近"的分数层修补全部失败（见 §8 的相关线）。

本主线问的是：**把某个查询的观测从"CLIP 排序掩膜池"换成"检测器文本框 → SAM 掩膜"，
能否改善？** 以及随之而来的三个子问题：

1. CLIP 与 Grounded-SAM 各自的 2D 限制、3D 上限、独立得分
2. 为什么 2D 上混合有效、3D 上无效；混合的最佳上限
3. 是否必须早期混合；能否保留两套语义在后面融合

---

## 2. 数据与协议

**数据集**：LERF-OVS 四场景（figurines / ramen / teatime / waldo_kitchen），208 个查询实例。

| 用途 | 来源 |
|---|---|
| 图像与 GT | `ref/hf_lerf/lerf_ovs/label/<scene>/<frame>.{jpg,json}`（evaluator 同源） |
| 掩膜池 | `VALA/dataset/3dgs/lerf_ovs/<scene>/language_features/<frame>_s.npy`（管线自己的掩膜） |
| 场与特征 | `ref/relags_hf/<scene>/sai_nag.pt` |
| 基线读端 | `--center none --text canon --topk 5 --level_until 3 --sel gap` |

**基线校验**：四场景 macro = **0.6401**，与官方 ReLaGS 锚点逐位一致。

**两臂**（注意：这不是同一任务的两个实现，见 §0.5）：

- **CLIP 臂**：对掩膜池内每张掩膜算 `cos(f_mask, t_query)`，取 argmax
- **GSAM 臂**：Grounding DINO（tiny，文本 `<query>.`，box/text threshold 0.08）取**分数最高的一个框**
  → SAM ViT-H 以该框为 prompt（3 个候选）→ 取 SAM 预测 IoU 最高的一张

**query 来源已核对**：208 条 `(scene, frame, name)` 与基线 `base_*.csv` 的 `(scene, image, prompt)`
集合完全相等（208/208，双向差集为空），即与评测器自己使用的测试 query 逐条相同。
`gt.sum() >= 100` 四场景均未触发（最小 723 px），不构成子集筛选。
GT 掩膜只用于最后评分，从不参与框或掩膜的选择。

**全程零拟合**：DINO 与 SAM 都是冻结权重，query 只在推理时进入，GT 只用于评分。
阈值敏感性：box/text threshold 在 0.05 / 0.08 / 0.15 下结果**逐位相同**，0.30 时只动 0.01。

**3D 评测**：把 2D 掩膜提升为高斯（查询视角投影 + 可见性 + z-buffer 遮挡），
在该视角重渲染，与 GT 掩膜算 IoU；按评测器口径先按图平均、再按场景平均、最后四场景取均值。

## 5. 门控：为什么 2D 有效、3D 无效

### 5.1 直接证据（同一批 30 条切换查询）

| | CLIP | GSAM | Δ |
|---|---:|---:|---:|
| **2D 掩膜 IoU 中位** | 0.000 | 0.319 | **+0.319** |
| **3D 渲染 IoU 中位** | **0.719** | 0.258 | **−0.461** |

**符号完全相反。** 关键：这批查询在 3D 上 CLIP 的中位是 **0.719，高于全体 0.6401**——
熵挑中的是"单视角掩膜排序很差、三维渲染反而很好"的查询。

### 5.2 根因：2D 与 3D 难度解耦

CLIP 的 2D 逐掩膜 IoU 与 3D 渲染 IoU 基本无关：簇选择是多视角聚合后的对象，
单视角 mask 打分差完全可以在三维上渲染得很好。**用 2D 难度当门控信号，从原理上就指错地方。**

### 5.3 端到端阈值扫描（2D 熵门控）

| 熵阈值 | 切换条数 | macro mIoU |
|---|---:|---:|
| ∞（不切） | 0 | **0.6401** |
| 4.60 | 30 | 0.6222 |
| 4.30 | 60 | 0.5942 |
| 4.00 | 94 | 0.5873 |
| 3.50 | 116 | 0.5663 |
| 2.84 | 145 | 0.5574 |

**任何阈值都低于基线，且随切换数单调变差。**

### 5.4 换到 3D 侧信号，同样无效

145 条可提升查询里 35 条 GSAM 更好。四种独立信号的判别力：

| 触发信号 | AUC →"切换有益" | AUC →"CLIP 弱(3D)" |
|---|---:|---:|
| 2D softmax 熵 | 0.609 | 0.762 |
| 场簇级 top1 | 0.513 | 0.404 |
| 场簇级 top1−top2 gap | 0.425 | 0.272 |
| 检测器自身置信度 | 0.561 | 0.392 |

**全部接近随机。** 注意第一列与第二列的分裂：2D 熵能较好预测"2D 上 CLIP 弱"（0.76），
但完全预测不了"3D 上切换有益"（0.61）——因为两者不是同一件事。

**结构限制**：场不知道帧，3D 侧统计量天然是（场景，类别）级；
54 个类别实例中仅 14 个 GSAM 更好，且是**强双峰**：

```
更好： pumpkin +0.958  hand +0.831  sake cup +0.783  tesla door handle +0.750
更差： coffee  −0.823  kamaboko −0.825  ketchup  −0.827  pour-over vessel −0.870
```

用检测器置信度做门控，最保守点（15/145 切换）0.6047→0.6192（+0.0145，阈值为测试集分位数，噪声级）。

## 6. 已排除的三种解释

| 解释 | 检验 | 结论 |
|---|---|---|
| 阈值太激进 | 从 30 次切到 145 次，全部为负 | 排除 |
| lift 缺遮挡测试（背面高斯撑大掩膜） | 加 z-buffer 后 0.6217→0.6222 | 排除 |
| 数据集/口径错误 | 早期版本误用 LERF-Mask；已改用 LERF-OVS 官方 label 帧与管线掩膜池 | 已修正 |

**另两处必须记录的实现细节**：

- `_f.npy` 是**按层拼接**的（如 ramen frame_00006 各层 unique id 46/88/43/19 合计 196，而 f 有 197 行），
  按全局 id 索引是错的；本轮改为对每个掩膜重算 CLIP 特征以绕开对齐问题。
- LangSplat 版 SAM 的 `predict(box=...)` 需要 **numpy**，不是 tensor；
  `scores` 直接是 numpy。

## 7. 对"是否需要早期混合 / 能否晚期融合"的回答

**Grounded-SAM 不是语义场。** 它没有跨视角聚合，也没有逐簇分数；
要让它产出"每个簇的分数"就必须做 2D→3D 提升 —— 而那正是失败的一步。

所以"保留两套语义、在多视角部分再融合"对 **CLIP + GSAM 不成立**，它只是把问题挪了位置。
晚期融合只对**两个真正的场**（如 CLIP 与 OpenSeg 各自 lift 出的特征场）成立，
因为那时两套分数同支持、同粒度。

---

## 8. 与本项目其他结论的关系

这条线是第三次"提高判决信息量 → 端到端失败"：

| 尝试 | 2D/分数层 | 端到端 |
|---|---|---|
| QTC 逐字实现（Engel 2026） | — | ramen 0.5548→0.4058 |
| MMD（按 margin 选裁剪） | — | 0.639→0.557 |
| **Grounded-SAM 重观测** | **0.803→0.878** | **0.6401→0.6222** |

三者共同点：在 2D/分数层拿到的东西，经 3D 读端后蒸发。
结合"共模在 argmax 中抵消""2D 与 3D 难度解耦"，可以统一成一句：
**LERF-OVS 的读端瓶颈不在单视角观测质量，而在簇级（多视角聚合后）的选择。**

## 10. 若要重开：前置条件

不是换阈值或换触发器，而是要满足其一：

1. **3D 侧的触发信号有判别力** —— 目前四种都没有。可能的候选：簇选择的半样本稳定性
   （本项目审计器用过的量）、簇的空间一致性。这些**尚未在 208 条上作为门控测过**。
2. **GSAM 在三维上有独立的聚合形式** —— 例如在多视角上分别 grounding、再按 3D 一致性融合，
   而不是单视角提升。这避开了"单视角量替换多视角量"的粒度失配。
3. **只在保留两套场的前提下融合**（CLIP + 另一个真正 lift 出的特征场），不属于本条线的范围。
