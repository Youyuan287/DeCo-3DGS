# 现有 3D-OVS 的严重问题（基于本轮实验的证据，2026-10-31）

## 0. 一句话

**3D-OVS 目前被实现成“用文本在已有候选里选区域”，而不是“先形成 3D 实例、再做开放词汇识别”。**
这导致三个后果：候选池没有的物体永远救不回来（recall 失败）、跨视角身份不可靠、评测也无法区分
“真的理解了 3D”还是“在查询视角上做了 2D 捷径”。

---

## 1. 问题一（最深）：缺少文本无关的 3D 实例形成

**现象**：候选由文本相似度在层级区域上生成；池内没有正确候选时，任何 rerank/gating 都无效。

**我们的证据**：
- recall 族 29/208（14%）池内最佳候选 IoU 仅 **0.027**；3D gateE 0.0198。
- released pool 的 oracle 只有 **0.7094**；即使每查询从池里挑最佳也到不了 0.71。
- 但 2D 信息是存在的：GT 最佳 2D mask 提升到 3D，deep **0.8247**、recall **0.2352**。

**含义**：物体实例本应先由 class-agnostic 证据（2D mask + 几何）形成，再用文本识别。
现在反过来了：文本先决定“哪些区域可能是物体”，漏掉的实例永远没有机会。
这是 3D-OVS 最根本的结构性问题，也是所有 rerank 类方法的天花板。

## 2. 问题二：跨视角“身份”没有可靠信号，一致性是伪不变量

**现象**：同物体跨视角余弦高，但不同类也高；用一致性做关联/聚合会选到共享/背景。

**我们的证据**：
- 2D mask 特征：same 0.60–0.76，diff 0.50–0.56；ramen 间隔仅 **0.066**，Fisher 0.615；
  跨视角检索 top1 12–20%。
- ROFA（一致性剔除）在官方读权上中性/空操作；在重建读权上 raw 略正但场景波动 ±14。
- 用跨视角一致性选 2D mask：text 0.4598 → xview 0.4003/0.3038，support-only **0.0251**。
- 一致性聚合把 2D 特征的 found 命中从 **77.4%** 打到 31.5%（均值保留 84.7%）。

**含义**：“跨视角一致 = 同一物体”这个假设在开放词汇特征上不成立。共享语义/背景反而更一致。
领域需要**几何/结构驱动的关联**（支撑重叠、可见性、lifting），而不是特征一致性。

## 3. 问题三：2D 与 3D 证据脱节

**现象**：逐视角 2D mask 很强，lifting 损失很小；但 3D 侧用区域混合特征，丢掉了 2D 的判别力。

**我们的证据**：
- 2D mask 文本 rank1：found 77.4%、deep 57.9%。
- 2D→3D lifting 全部 208 查询平均只损失 **0.049 IoU**（found −0.05、deep −0.03）。
- 但 3D 候选聚合的一致性信号 found 仅 31.5–46.8%；简单均值 84.7%。
- **3D 最佳候选 IoU（0.708）甚至高于 2D 最佳 mask（0.635）**——表示层不是瓶颈，关联/选择才是。

**含义**：3D-OVS 没有把 2D class-agnostic 分割当作一等公民。缺少“2D mask → 3D 实例”的
原则性关联（mask graph/track），只在区域层级上做特征平均。

## 4. 问题四：评测协议不可复现，且不真正测 3D

**现象**：同一方法在不同未公开选择下，单场景可差 4–5 分；评测只在查询视角渲染。

**我们的证据**：
- 官方读权无法由发布产物重建：官方 level-0 **7852** 超点 vs 发布 `nag-l1.pt` **7936**；
  ramen 重建 0.4935 vs 官方 0.5115。
- C1 开/关：figurines 58.59 vs 63.29、waldo 65.92 vs 60.62，macro 却几乎相同——
  单场景结论可以被协议翻转。
- topk=5→3 掉 4.25 分；`remove_small` 在 figurines 上差 16.5 分；论文未发布评测代码。
- 查询 mIoU 没有置信区间；我们的 bootstrap 常见 ±1–2 分，很多“提升”在噪声内。
- 评测在**查询视角**渲染，而该视角的 2D mask/GT 可用——方法可以使用查询视角 2D 证据，
  benchmark 无法区分“3D 理解”与“2D 捷径”。

**含义**：领域缺一个**协议冻结、特征发布、带置信区间、且在novel view/instance level 评测**的基准。
否则方法间的 1–2 分差异不可信。

## 5. 问题五：指标只测“查询 mIoU”，隐藏了 recall/实例发现问题

**现象**：所有方法只报 query mIoU；没有实例级 precision/recall、没有 open-set 拒识、没有校准。

**我们的证据**：recall 29 条在 mIoU 里只贡献 0.02，但它们是“完全没找到物体”；
found 124 条已经 0.83，继续优化对总分影响小。mIoU 把“没找到”和“找到了但边界差”混在一起。

**含义**：需要 instance-level 指标（discovered/recall、false-positive per query、calibration），
否则方法会优化 deep/rank2 的边界，而忽略 14% 的根本失败。

## 6. 问题六：特征/协议不透明，复现成本极高

**现象**：官方只发布聚合后的 `sai_nag.pt`，不发布逐视角特征、mask 预处理、评测代码；
不同 CLIP 版本/分区导致 1.5–5 分差异。

**我们的证据**：重建读权与官方簇数不同（1853/507/249 vs 1858/491/248），无法对齐；
复现报告中的 55.38 是剪枝阈值用错，64.01 依赖发布读权。任何“改进 ROFA”的实验都无法锚定。

**含义**：领域需要**特征/协议/读权生成的标准化发布**，否则方法比较没有共同底座。

---

## 7. 最值得解决的问题（排序）

1. **文本无关的 3D 实例形成与跨视角关联**（问题一+二+三）：
   用 2D mask 图 + 几何兼容性建立 3D instance track，再用文本识别。
   这是唯一能解决 recall、并把 macro 从 0.676 推向 0.75+ 的路线。
2. **评测协议与指标**（问题四+五）：
   novel-view / instance-level / 置信区间 / 冻结协议；否则领域的数字不可比。
3. **特征与读权发布标准**（问题六）：让改进可被独立复现。

## 8. 我们能立刻做的切入点

- **mask 图 → 3D track → 文本打分**：节点=逐视角 SAM mask，边=lift 后 Gaussian 支撑重叠
  （几何，不用特征一致性），连通分量/谱聚类成实例；实例级文本打分。直接针对 recall。
- **instance-level recall 指标**：把 29 条 recall 失败显式报出来，而不是被 mIoU 平均掉。
- **novel-view 评测**：在未标注视角渲染，检验是否真的 3D 一致，而不是查询视角 2D 捷径。

一句话：**3D-OVS 现在缺的不是更好的 CLIP 特征，而是“物体从哪里来、跨视角怎么认成同一个”这一层。**
