# LERF 集合选择（Inclusion v1）尝试报告（预注册，FAIL）

日期：2026-10-30
预注册：`analysis/PREREG_inclusion_v1.md`（先冻结后跑）
目标：直接学习 GT-greedy 最优子集成员，试图缩小 C（0.6590）与 greedy5 oracle（0.751）之间约 9 个点的差距。

## 1. 训练信号与统计

- 用 GPU 逐查询计算 GT-greedy 子集（按与 GT 的并集 IoU 贪心，≤5 次添加）。
- 208 查询：greedy 平均 IoU 0.751 vs main 0.626（逐查询）；**71 条有提升、137 条已最优**；
- 最优子集大小：平均 1.10，**74.5% 是单例**；|S|≥2 的仅 33 条；20 条为空集（零 IoU 候选，召回族）。
- 候选级分类器（LOSO，GBM）：正类率 0.208；在 P≥0.5 下平均选出 1.37 个候选，对 greedy 成员的召回率 0.832。

## 2. 测试结果（冻结规则，无调参）

| 方法 | 场景平均 | Δ vs main | 95% CI | 胜负 |
|---|---:|---:|---|---|
| main | 0.6396 | — | — | — |
| 当前方法 C | **0.6590** | +0.0240 | [+0.0061,+0.0452] | 23/9 |
| R_inc（gap ∪ P≥0.5） | 0.6351 | −0.0019 | [−0.0103,+0.0030] | 2/2 |
| R_inc_prune（C + 并入） | 0.6545 | +0.0221 | [+0.0025,+0.0430] | 25/11 |

- 纯并入几乎不生效（仅 4 条查询改变），对 deep/rank2 零帮助；found −0.004。
- 并入叠加到 C 上反而低于 C（0.6545 < 0.6590），说明并入的候选与 C 的剪枝/尺度并入冲突，互相抵消。
- 门控四项：Δ≥+0.02 FAIL、无场景恶化 FAIL、found PASS、超过 C FAIL → **VERDICT FAIL**。

## 3. 为什么学不会 greedy 子集

1. **目标本身稀疏**：74.5% 的最优子集是单例，训练信号主要集中在"top-1 是否正确"（分类器 found 保留很高），而真正需要加候选的只有 33 条查询。
2. **特征无法识别"该加的那一个"**：greedy 成员在 deep 族往往是低分候选，与无关候选在现有特征（分数/面积/身份一致性）上不可分；这正是此前证据审计的结论。
3. **加入的代价不对称**：多标签并入错误候选会稀释 IoU（R_inc 的 found −0.004 与 2 胜 2 负），而正确并入只在少数查询发生。

## 4. 结论

- **集合选择线（阈值规则 → 回归器阈值 → 成员分类器 → 并入）全部尝试完毕且未通过门控**；C（Prune-and-Include）仍是 4 场景上的峰值（+2.40，预注册通过）。
- 继续在这批场景上做选择层改动已无统计空间；剩余涨点只能来自**候选生成本身**（13.9% 查询池内无正确对象，oracle 单候选 0.71）或更多场景。
- 建议：锁定 C 为论文方法版本；将本报告与 Inclusion v1 的负结果写入论文分析/future work。
