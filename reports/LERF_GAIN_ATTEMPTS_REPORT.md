# LERF-OVS 涨点尝试报告（三条预注册路线，均未通过门控）

日期：2026-10-30
预注册：`PREREG_pool_depth.md`、`PREREG_poolgen.md`、`PREREG_subset_selector.md`（均先冻结后跑）
基线：released DeCo main，场景平均 0.6396（逐查询口径 0.626；各实验重算的 s0/gap5 与 main 逐查询完全一致，最大差 ~1e-16）。

## 1. 池深扩展（gap@10 / gap@20）

| 方法 | 场景平均 | Δ vs main | 说明 |
|---|---:|---:|---|
| main（gap@5） | 0.6396 | — | 基线 |
| gap@10 | 0.6385 | −0.0011 [−0.0133, 0.0098] | 4 胜 3 负 |
| gap@20 | 0.6292 | −0.0105 [−0.0153, 0.0034] | waldo −4.4 个点 |

结论：更深池子里的候选不会被 gap 规则选中（gap 长度基本不变），oracle 的 greedy20 +14 点不可由"换池子 + 原规则"获得。**FAIL**。

## 2. 候选生成阈值网格（12 配置，LOSO 选参）

网格：root 最小点数 {50,20,10} × 叶提升比例 {1%,0.5%} × 池深 {5,10}，选择规则固定为 released gap。

- 全网格场景平均：0.6294–0.6401，最好的 0.6401（mp50_lr0.005_n5、mp10_lr0.005_n10）；
- LOSO 选参（3 折选 mp10_lr0005_n10，1 折选 mp20_lr001_n10）：留出场景平均 0.6394，**Δ = −0.0002，CI [−0.0123, +0.0112]**；
- 分族：cut_early +0.034、cut_late +0.007、ok_gap −0.005；召回失败族没有恢复。

结论：调阈值救不回 13.9% 的召回失败，收益全部被正常查询的小幅损失抵消。**FAIL**。

## 3. 学出来的集合选择器（LOSO IoU 回归，明确标注为 learned probe）

- 回归器诊断：LOSO GBM 预测候选 IoU，单候选选择场景平均 0.6039，**found 保留率 0.984、hard rescue 0.418**（远好于零参数融合的 0.74/0.53）——它学会了"何时保留 top-1"。
- 集合规则（预注册）：S1 = gap 前缀 ∪ {pred ≥ max_pred 且 pred ≥ 0.5}；S2（诊断）阈值 0.4；S3（诊断）pred ≥ max_pred。
- 结果：

| 规则 | 场景平均 | Δ vs main | CI | 备注 |
|---|---:|---:|---|---|
| S1（主） | 0.6315 | −0.0034 | [−0.0103, 0.0000] | waldo −3.2 |
| S2 | 0.6315 | −0.0034 | 同上 | 与 S1 等价 |
| S3 | 0.6432 | **+0.0117** | [−0.0036, +0.0306] | ramen +3.5、figurines +1.2、**waldo −3.2**；4 胜 3 负 |

S1 三项门控全失败；S3 虽然点估计 +1.17，但置信区间跨零、单个场景显著恶化（waldo −3.2），按预注册判定 **FAIL**。S3 是一个"接近但不成立"的信号，按纪律不在本批场景上继续调。

## 4. 总体判断

1. **released gap + top-5 是一个局部最优点**：池深、阈值、选择规则、学出来的集合增量，所有局部旋钮的移动都在 ±1 个点内，且没有一次同时满足"均值提升 + 置信区间 + 无场景恶化"。
2. **方差被小场景主导**：waldo_kitchen 只有 22 条查询，任何规则都会在它上面放大成 3–4 个点；ramen 是收益的主要来源。这让"稳定涨点"在 4 场景 208 查询上很难成立。
3. **剩余空间在候选生成本身，而不在池参数**：13.9% 查询池里没有正确物体（oracle greedy20 也只有 0.196），阈值网格无法恢复。真正的涨点需要新的候选提案（多视角 mask 融合、分割细化、合并/拆分），预期 +2~4，但那是新的分割管线，不是本管线的参数。
4. **学出来的选择器**（S3 形态）是唯一有正向迹象的决策层方案（+1.17，ramen +3.5），但需要更多场景才能证明；如果目标是论文数字，这条线应在 ScanNet（10 场景）上先做跨数据集确认，再回 LERF，而不是继续在 4 场景上调。
