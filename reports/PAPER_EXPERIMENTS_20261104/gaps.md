## G1. ScanNet 的四个基线：40.36 / 43.88 / 40.79 / 39.94

| 数 | 来自哪条链 | 聚合 | 含义 |
|---|---|---|---|
| 41.26 | ReLaGS 论文 Table 9 | pooled | 已发表值 |
| 40.79 | `github_clone3/deco/scannet/`（shipped harness） | pooled | **我们的复现锚点** |
| 39.94 | 同上 | macro | 同一场的另一种聚合 |
| 43.88 | 认证消融链 `v2_off_off` | pooled | 另一条场（`scannet_v2_certified_20261029`） |
| 40.36 | 认证消融链 `v2_off_off` | macro | 同一场的 macro |

**为什么差**：不是误差，是两件事叠加。

1. **聚合不同**：pooled 先按类累加 intersection/union 再对 18 个类平均；macro 先场景内平均再场景间平均。
   pooled 更奖励大类，而增益恰好集中在大类，所以两者差约 4 分且方向一致。
   `github_clone3/deco/PROTOCOLS.md` §1 明确规定两者不可互换。
2. **场不同**：shipped harness 与认证消融链是两条 10–scene 场。同一聚合下差 0.4（macro）
   到 3.1（pooled）。

**另外**：K19 的除数是 **18 不是 19**，因为 `bookshelf` 在十个场景的 GT 与原始
`*_vh_clean_2.labels.ply` 里都是 0 个点（核过两次）。若坚持 19 除数，把所有均值乘 18/19：
58.55→55.47、40.79→38.64，增益变成 +16.82。

**用哪个**：主表用 40.79（P5）与 39.94（P6），并注明除数 18。40.36/43.88 只在
"认证链"这一节出现，且必须同时标 pooled/macro。

证据：`github_clone3/deco/RESULTS.md` §1–§2、`PROTOCOLS.md` §1、
`reports/FINAL_SEED1234.md`。

## G2. 50.18 vs 58.55：C1 的实现错了

这是全部冲突里影响最大的一条。

| 版本 | C1 做什么 | macro | pooled |
|---|---|---|---|
| 早期认证链 | 逐**视角 mask** 均值中心化 | 40.36 → 50.18 (+9.82) | 43.88 → ~54 |
| 正确实现 | 区域轴（cluster）中心化 | 39.94 → 53.30 (+13.36) | 40.79 → 58.55 (+17.76) |

**为什么差**：`deco_ops.center_np` 的注释写明 C1 作用在 `nag_feat`（每个簇一个向量）上，
是**区域轴**中心化；早期把"逐视角 mask 特征的均值"当成 C1，作用对象错了。
`experiments/cvpr27_8h_discovery/` 的记录：用错算子时 CLIP 的 C1+C2 只有 +3.6，
改对后 +16.7，与官方 +9.8 同号同量级。

**为什么 53.30 与 58.55 又不同**：同一个算子的 macro 与 pooled，见 G1。

**用哪个**：论文写 58.55（pooled，主）与 53.30（macro，附）。**不要写 50.18**；
若必须提早期版本，写"我们的第一版把 C1 作用在逐视角 mask 均值上，只得到 +9.8"。

证据：`results/scannet_c1c2_ablation_20261103/c1c2_ablation.json`、
`reports/CVPR_DRAFT_DECISION_AUDIT_20261102.md`、
`experiments/cvpr27_8h_discovery/19_BEST_METHODS_AND_RESULTS.md` §E。

## G3. 58.55 vs 56.05：锚点依赖一个已经不在盘上的场

**事实**：`58.55` 需要 shipped `clip_cache` 对应的 **366 簇**场；盘上 `nag` 是 **386 簇**，
直接套用会 IndexError。用当前产物重建缓存后，官方 scorer 在十场景上给
**56.05 pooled / 49.89 macro**，而且 **renorm 顺序翻转**：锚点是 58.55 > 57.85，
重建场是 56.05 < 56.59。

**为什么差**：簇数从 366 变 386 改变了若干超点的文本分配；同时 `renorm 0/1` 的
τ-LSE 非齐次性（PROTOCOLS.md §4.1）让顺序对小扰动敏感。

**用哪个**：表里分两行。锚点行（S-02…S-08）标 **R3**，重建行（S-09…S-12）标 **R1**。
正文主结果用锚点并注明"复现需 366 簇场"，补充材料给重建行。

证据：`reports/SCANNET_*` 与记忆条目 `scannet-candidate-ceiling`；产物
`results/scannet_repro_20261103/`（20 个 JSON）。

## G4. zR 45.98 vs C1 53.67：两个不同的算子

| 算子 | 数学形式 | 作用空间 | 增益 | 底座 |
|---|---|---|---|---|
| zR | `S'[g,c] = (S[g,c] − mean_g S[g,c]) / std_g S[g,c]` | **分数**空间 | +5.62 (45.98) | 40.36 |
| C1 | `f ← f − mean_cluster(f)`，再投影 | **特征**空间 | +12.88 (53.67) | 40.79 |

**为什么差**：zR 在分数矩阵上按类做标准化，只能去掉每类的尺度与均值；
C1 在特征空间去掉区域轴上的共同分量，同时改变所有类的分数。在一词一类的读端下二者
在 argmax 上近似等价（都等价于减某个全局向量）；但 C2 的 τ-LSE 多词边际化不是齐次的
（`LSE_τ(c·a) = c·LSE_{τ/c}(a)`），所以两者在真实读端上分开。

**用哪个**：C1（53.67 / 58.55）是方法。zR 只作消融里的"score 侧次优解"，并注明它的
独立增益只有 C1 的 44%。注意两条底座也不同（40.36 vs 40.79）。

证据：`experiments/cvpr27_8h_discovery/19_BEST_METHODS_AND_RESULTS.md` §A1、
`results/scannet_c1c2_ablation_20261103/`。

## G5. 48.77 vs 47.49：文本空间用错了

**事实**：证据脚本用了 `utils.vlm_utils.text_features(...)`，而 released 读端用的是
`text_bank.npz`；同一个类名的两个嵌入余弦只有 **0.495**。修正后：
zR 45.98 → zR+E0 **47.49**（+1.51），不是 48.77（+2.79）。

**为什么差**：两个文本空间不是同一个函数；证据项与被加分的 released 分数不在同一坐标系，
差值被系统性放大。

**用哪个**：**47.49**。`19_BEST_METHODS_AND_RESULTS.md` 把这条列为"本轮最严重的自我纠错"。
`experiments/cvpr27_8h_discovery/RESULTS.md` 与 `01_BASELINE_AND_FAILURE_AUDIT.md` 里
仍有 48.77 的残留，读到时以 47.49 为准。

## G7. LERF-OVS 的六个"主结果"

| 数 | 协议 | 是什么 | 能不能报 |

## G8. 0.6401 vs 0.5565：集合读端 vs 单候选读端

`0.6401` 是 gap 规则选出一个**集合**再渲染；`0.5565` 是每次只看 rank-1 一个候选。
后者是 `analysis/lerf_visibility_prefix_eval.py` 等探针用的 in-harness 口径，
用来判断"候选级算子能不能选出池里最好的那个"。

**为什么差 8 个点**：gap 集合本身贡献了大部分分数。任何"单候选算子"（边界判据 J、
MMD、逐视角胜率、几何描述子）的上界都是 0.5565 这一列，**不能拿它去和 0.6401 比**。
这也解释了为什么很多"看起来失败"的探针其实没有测错——它们测的是另一个问题。

**用哪个**：主表只用 0.6401；0.5565 及其变体只进诊断表。

## G10. 3D-OVS 的 70.05 / 92.5 / 66.7

**为什么差 22 分不是协议错误**：`--mode oracle` 把投影落在 GT 内的全部高斯选上，
bed 得到 **0.9594**，与论文的 94.4 一致 ⇒ GT mask、相机内外参、渲染、分辨率（r4）、
IoU 协议全部正确。差距在**语言场的特征分辨率**：每视角 mask 数 bed 53 / bench 412 /
lawn 598 / room 72 / sofa 131（健康线 >100），level-1 簇级 oracle 只有 0.7735。
同族 THGS 复现 66.7，与我们 70.05 一致，说明这是这一族管线的共同水平，不是我们独有的 bug。

**为什么重编码救不回来**：编码器的 NMS（`masks_update`，iou/score/inner 三重过滤）把每视角
区域数结构性地锁在 ~40；pps 32→64 后只从 53 到 57，文本选择反而 61.24→44.36。
这是"稀疏分区 vs 逐像素场"的表示形态差异，不是参数问题。

**用哪个**：基线写 70.05，并明确标 P8 与"复现差距在特征分辨率"。任何 3D-OVS 上的
方法结论（包括审计的 −6.5）都要注明"前提未成立"。

## G11. OpenSeg 的三个数：61.64 / 55.77 / 47.05

| 数 | 含义 |
|---|---|
| 61.64 | OpenSeg-768 场的**基线**（十场景，K19 pooled） |
| 55.77 | 旧草稿里的 OpenSeg 结果，已被 61.64 取代 |
| 47.05 | 把 C1/C2 **强行**作用到 OpenSeg 场的结果（−14.59） |

**为什么 47.05 是负的**：OpenSeg 的 CMR 只有 1.13（CLIP 是 2.14），说明它已经校准过、
没有可去的共同分量。这正是 CMR 门控（阈值 1.6）存在的理由——门控在 OpenSeg 上会关闭，
所以这一臂应写成"**适用域之外**"，而不是"方法失败"。

**为什么 OpenSeg 仍值得提**：它是唯一一个把"换编码器"这个通道测出大效应的实验：
未校准 CLIP 40.36 → OpenSeg 55.77/61.64 是 +15 以上，比框架内九个杠杆（全部 ≤5）大 2–3 倍。
但它救不了 door/window/table（完全不动），与干净裁剪实验一致。

**用哪个**：基线 61.64；47.05 作"门控关闭"的证据；55.77 不再引用。

## G12. 逐查询 CSV 的朴素均值 0.6337 不是 0.6401

`analysis/results/20261101/cnone_gate_tf/*.csv` 共 208 行。直接对 `main_iou` 取算术平均
得 **0.6337**（另一批文件是 0.6257）；按 P1 口径 **query 内平均 → image 内平均 →
scene 内平均 → scene 间平均** 得 **0.6401**。

**为什么**：每条 image 的 query 数不同，逐 query 平均会给查询多的 image 更大权重；
官方 `eval_seg.py` 的 `mIoU` 是先图内平均。日志里的 `flat=` 列就是这个差异（约 0.6 分）。

**用哪个**：0.6401。`verify.py` 里有一条专门的 guard 断言"朴素均值 ≠ 嵌套均值"，
防止以后有人改回朴素平均而悄悄破坏锚点。

## G13. Grounded-SAM 的 0.925 用错了数据集

**事实**：此前记录的「CLIP 失败组 0.000 → Grounded-SAM 0.916 / 中位 0.925」全部跑在
`datasets/lerf_mask`（**LERF-MASK**）上，不能与 LERF-OVS 的 64.01 对应。在 LERF-OVS
四场景 208 条上重跑（GT 与图像取 `ref/hf_lerf/lerf_ovs/label`，掩膜池取管线自己的

|---|---:|---:|---:|

## G14. 空渲染 +4.2 是单候选伪影，官方读端只有 +1.50

**事实**：单候选诊断口径下「丢弃空渲染」把 0.5565 抬到 0.5982（+4.2），但这不是官方读端。
在官方 gap 前缀并集读端上（base 0.6401，与锚点逐位一致）：

| 变体 | macro | 配对差 |
|---|---:|---:|
| base | 0.6401 | — |
| V1 删掉本视角不可见的前缀成员 | **0.6401** | 0.0000（逐像素相同） |
| V2 按可见性重排后重求 gap | 0.6368 | +0.0025 CI [−0.022,+0.028] |
| V3 前缀全空时回退到最好的可见候选 | 0.6524 | **+0.0150** CI [+0.0018,+0.0314] |

V1 与 base 逐像素相同 ⇒ 不可见簇本来就贡献 0 像素，官方并集早已"忽略"它们；
诊断口径里 46.5% 的空行是**单候选渲染**的伪影。

**V3 的定性**：+1.50、5/208、单场景（全在 ramen）、CI 下界 +0.0018——正是本项目判定为噪声的
形态；而且它让选择变成视角相关（官方 `search()` 不吃相机参数），方法层面自相矛盾。
**写成读端 sanity guard，不写成贡献。**

**用哪个**：主表不出现 +4.2。若讨论空渲染，写 18/208（8.7%）预测为空，其中 10 条可选择救回、
8 条是覆盖缺陷。

证据：`results/lerf_visibility_20261104/*_official.csv`、`22_EMPTY_RENDER_GUARD_RESULT.md`。
