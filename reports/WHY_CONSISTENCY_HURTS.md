# 为什么 2D 好、3D 聚合差？为什么一致性把 found 从 77.4% 打到 31.5%？

## 0. 先纠正一个口径

“2D 好”和“3D 差”不是同一件事的直接对比：

- 2D 的 77.4%：**GT 最佳 mask 在该视角所有 mask 中被文本排到第 1** 的比例（found 族 96/124）。
  这是“给定正确 mask，特征能不能被文本认出来”。
- 3D 的 31.5%：用**一致性聚合后的特征**在候选池里选中 GT 最佳候选的比例（found 族）。
  这是“聚合后的特征还能不能认出物体”。

两者任务不同，但可以做一个**受控对比**：同一批逐视角 mask 特征、同一候选池、同一文本，
只换聚合算子：

| 聚合方式 | 是否查询条件化 | found 命中 | deep 命中 | 说明 |
|---|---|---:|---:|---|
| 2D 单视角文本 rank1 | 是（文本） | **77.4%** | 57.9% | 无聚合，逐视角 |
| 3D id_top3 | 是（文本 top-3） | **86.3%** | 52.6% | 逐视角文本 top-3 均值 |
| 3D id_mean_c | 是（文本加权均值） | **84.7%** | 15.8% | 中心化后的均值 |
| 3D id_mean | 是（可见性加权均值） | 78.2% | 21.1% | 原始均值 |
| 3D agree_c | **否（跨视角一致性）** | 46.8% | 26.3% | 一致性剔除后均值 |
| 3D agree | **否（跨视角一致性）** | **31.5%** | 21.1% | 一致性剔除后均值 |

**关键结论**：3D 聚合本身不差。查询条件化的聚合（id_top3 86.3%、id_mean_c 84.7%）
甚至高于 2D 的 77.4%。**崩掉的是查询无关的一致性聚合（31.5%）。**
所以问题不是“加权均值 vs 最好的 mask”，而是**权重依赖什么**。

## 1. 为什么一致性聚合会把 found 打崩

一致性聚合的权重/保留规则只依赖“视角之间像不像”，**完全不知道当前 query 是什么**。
在区域/掩码混合特征上，这会导致四个连锁效应：

1. **它优化的是“共享成分”，不是“物体成分”。**
   区域特征 = 物体 + 背景/场景共享语义。跨视角最一致的部分往往是共享语义
   （墙、桌面、房间光照），而不是物体。q_i 的分布很紧（只剔除 4.8%），
   被剔掉的尾部恰恰是“和共识不一样”的视角——也就是物体最显著、最独特的视角。
2. **剔除后，聚合特征向场景原型靠拢。**
   保留下来的是“最像大家”的视角，均值更接近 scene prototype；
   文本对齐（object-specific）反而下降，通用/背景候选的分数上升。
3. **found 查询本来已经排对，任何查询无关的扰动都在破坏它。**
   found 的 released 选择是正确的；一致性特征在 68.5% 的 found 查询上选中了另一个候选
   （命中率 31.5%）。这不是“微调”，是把已经对的排序翻掉。
4. **它偏爱大区域/多视角候选。**
   视角越多、区域越大，越容易形成“共识”；小物体、少见视角的候选被系统性压制。
   这与 found 查询里小物体的失败方向一致。

**因果性**：上表是同一特征、同一池、同一文本，只换算子。id_top3 86.3% → agree 31.5%
的落差只能由“一致性算子”本身解释，不是特征差、不是池差。

## 2. 更深的原则：开放词汇的身份是“查询相对的”

同一个区域，query 是 “table” 还是 “plate”，哪些视角是“有效证据”是不同的。
- **查询条件化**（文本 top-k / 文本加权）：知道当前要找什么，保留对该 query 有证据的视角。
- **查询无关**（一致性、中心化、scene prototype、白化）：不知道 query，只能优化“大家共同的部分”，
  于是收敛到共享语义。

这解释了此前所有“中性/失败”的结果：
- C1（减 scene mean）对检索排序是常数平移 → 不改变结果；
- ROFA（一致性剔除）中性/空操作；
- 白化破坏文本对齐；
- 一致性选 2D mask 反而更差（xview 0.4003/0.3038，support-only 0.0251）；
- 一致性聚合 found 31.5%。

**一句话：一致性是“关联先验”，不是“评分权重”。**
它应该用来分组/建实例（association），不应该用来聚合特征做文本打分（scoring）。

## 3. 可检验的预测

如果上述机制成立：

1. **按文本加权的一致性**（保留文本证据强且相互一致的视角）应当优于纯一致性，
   并接近/超过 id_top3。
2. 一致性造成的 found 下降，应当在“物体占区域比例小、视角数多、背景共享强”的查询上更大。
3. 用一致性只做**分组**、聚合仍用文本权重，应当不伤 found。
4. 同一个区域换 query，文本 top-k 选中的视角集合应显著变化（查询相对性）。

## 4. 应该怎么做（方法含义）

- **评分路径**：永远用查询条件化的权重（文本 top-k 或 softmax 文本权重）聚合原始 CLIP 特征。
- **关联路径**：用几何/一致性把视角/mask 分组成实例，但分组后的评分仍回到文本。
- **不要**把一致性分数、scene prototype、白化后的特征直接送进文本打分。

这条原则同时解释了“2D 好 3D 差”的错觉：真正差的是**查询无关的 3D 聚合**；
查询条件化的 3D 聚合（id_top3）已经不比 2D 差。剩下的差距在候选池/实例形成，而不在聚合算子本身。
