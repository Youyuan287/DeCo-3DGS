# 3D-OVS 复现差距诊断与审计前提（2026-11-02）

目的：解释复现 70.05 与论文 95.4 的差距，并说明在这个前提下审计结论是否有效。
结论：**GT/相机/渲染/协议都是对的（逐高斯 oracle 0.9594 ≈ 论文 94.4），NAG 也够细
（level-0 簇 oracle 0.9245），差距在语言场的特征分辨率**：特征只到 level 1（每视角 53 个
mask），其簇级天花板只有 0.7735。在这个 field 修好之前，3D-OVS 上的任何方法比较（包括审计）
都不是有效测试。**且重编码在本管线内无效（§1.2）：编码器 NMS 把每视角区域数锁在 ~40，
pps/阈值都改不动；重编码后 prompt 0.61→0.44、oracle 0.77→0.56，反而更差。**

## 1. 决定性证据：三级 oracle 分解（本轮新增）

| 上限测试 | 选取单位 | bed mIoU |
|---|---|---:|
| 逐高斯 oracle（投影在 GT 内的全部高斯） | 503k gaussians | **0.9594** |
| 簇级 oracle，level 0（最细，7192 簇） | 7192 clusters | **0.9245** |
| 簇级 oracle，level 1（2211 簇，**特征最细层**） | 2211 clusters | 0.7735 |
| 簇级 oracle，level 2（149 簇） | 149 clusters | 0.7776 |
| 当前复现（文本选择，gap2 topk200） | level 2–3 簇 | 0.6124 |

结论逐层清晰：

1. **GT/相机/渲染/协议全对**（0.9594 ≈ 论文 94.4）；
2. **NAG 几何足够细**（level 0 可到 0.9245）；
3. **语言特征只到 level 1**（每个视角 53 个 mask；level-1 上限 0.7735）；
4. 文本选择在 0.61——在 level-1 天花板之下。

**根因：语言场的特征分辨率**（每视角 mask 数太少），不是搜索规则、不是协议。
验证：bed/bench/lawn/room/sofa 每视角 mask 数为 53 / 412 / 598 / 72 / 131
（HANDOVER 的健康线是 >100；bed、room 低于线）。

## 1.2 重编码尝试（pps 32→64）与探针：本管线内走不通

按"提高特征分辨率"的思路重编码了 bed（SAM `points_per_side=64`、`iou_thr=0.65`、
`stab_thr=0.80`、`min_area=50`，输出到 `data/3DOVS_fine`，不动原产物），复用几何层级、重跑
`merge_proj` 重建 NAG 后评测：

| 指标 | 原场（pps=32） | 新场（pps=64） |
|---|---:|---:|
| 每视角区域数 | 53 | **57** |
| 文本选择 prompt mIoU | 0.6124 | **0.4436** |
| level-1 簇级 oracle | 0.7735 | **0.5640** |

重编码不仅没抬天花板，反而更差。单图探针（同一张图，改 NMS 参数）给出了原因：

| 生成 | 原始 mask（4 层） | NMS 后保留 |
|---|---|---|
| pps=32 | 123 / 117 / 39 / 9 | 11–33 |
| pps=64 | 158 / 149 / 42 / 10 | 13–43 |
| iou_thr 0.7–0.9、score_thr 0.4–0.5 | 同上 | **仍为 13–43** |

**编码器的 NMS（`masks_update`，iou/score/inner 三重过滤）把每视角区域数结构性地限制在
~40 个**，与 `points_per_side`、score 阈值基本无关。也就是说这套管线产出的是"稀疏、互不重叠
的分区"，不是论文逐像素读出所依赖的稠密特征场。

由此可以判定：**在本复现管线的编码器内重编码，无法把 3D-OVS 从 0.61 拉到 0.94**。
差距不在协议、不在选择规则、也不在 SAM 密度，而在**语言场的表示形态**（稀疏分区 vs 逐像素）。
另外，merge 的层级构建也依赖特征（`assign_label` 用 view features 建邻接），所以换特征会
同时改变层级——重编码的副作用比预期大。

原产物 `data/3DOVS` 与 `output/3dovs` 未被改动；新产物在 `3DOVS_fine/3dovs_fine`，闸门未过，
其余四个场景没有启动（按约定）。

### 1.3 最细层（level 0）检索：假设被证伪

给原始场补算 level-0 特征（`merge_proj_l0.py`，`nag_feat` = [7192, 2207, 151, 66]），
在 level 0（7192 簇，簇级 oracle 0.9245）上做文本检索：

| 选择 | mIoU |
|---|---:|
| z-score 阈值 k=2（平均选 175 簇） | **0.5217** |
| top-200 | 0.4789 |
| top-100 | 0.4608 |
| 原 level-1 检索（对照） | 0.6124 |

**level-0 检索反而更差**。结论：即使到了最细的簇粒度，这套编码器产出的特征（每视角 ~40–60 个
mask）也无法支撑高精度文本检索。所以"ReLaGS 92.5 来自最细层检索"不成立；在已发布代码 + 同一
数据 + 同一编码器下，我们复现不出 92.5，而同族 THGS 的复现（66.7）与我们（70.05）一致。

### 1.4 数字对照的更正（重要）

重读 ReLaGS 表 13：**均值是最后一列 92.5，不是 95.4**；带 `*` 的是 **room**（不是 lawn）。
正确对应：Bed 95.4 / Bench 94.4 / Lawn 91.2 / Room 94.8* / Sofa 86.9 → Mean 92.5。
我们：Bed 56.4 / Bench 75.8 / Lawn 73.2 / Room 78.1 / Sofa 66.8 → Mean 70.05。
THGS（同族复现）：Bed 68.9 / Bench 67.6 / Lawn 73.9 / Room 68.4* / Sofa 54.6 → Mean 66.7。

## 4. 审计在 3D-OVS 上的结果为什么不可用

`3DOVS_DECISION_AUDIT_NEGATIVE_20261102.md` 报告审计把 70.05 打到 63.51。
在当时我们以为 baseline 是合理的；现在看，**这个 baseline 本身是 0.61–0.63 的坏选择**，
而证据排序（VL-Fields 同源特征）与 released 排序高度相关，改判只是在坏选择之间互换。
因此那次"证书全票却掉 14 分"的结论仍然成立（证书 ≠ 正确性），但**不能用来判断方法在
3D-OVS 上有没有价值**——前提没成立。

## 5. 下一步（按顺序，每步都可判定；第 1 步已完成）

1. ✅ **簇级上限测试已完成**（见 §1）：level-0 0.9245 / level-1 0.7735 → 根因是
   **特征分辨率**（每视角 mask 数），不是 NAG 粒度、不是搜索规则。
2. **重编码语言场**：提高每视角 mask 数（SAM 自动掩膜 / 逐像素 VL-Fields 特征），
   目标：level-1 簇级天花板 ≥0.90。这是把 3D-OVS 拉到 90+ 的唯一路径；
   在当前 53–131 mask/视角的场上，任何选择方法都到不了 0.94。
3. field 修好后再做审计：官方协议是**逐像素相似度 + 阈值**，审计应作用在
   "阈值化 mask"这一层（多视角一致性证书），而不是超点集合。
