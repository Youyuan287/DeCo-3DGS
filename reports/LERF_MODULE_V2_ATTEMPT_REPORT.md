## 3. 总体判断与下一步

1. **方法 C 仍是这 4 个场景上的峰值**（+2.40 场景均值，预注册门控通过）；本轮所有关于常数、并入通道、回归器的改进尝试都失败。
2. 继续在同一批场景上做局部改动（阈值/特征/规则）已进入过拟合区，按纪律停止。
3. 若还要显著涨点，只有两个方向，且都不属于"小改动"：
   - **更深候选池 + 重新训练选择器**：greedy20 oracle 0.774（比 C 高约 +11 点），但需要为 6–20 名的候选导出特征与 IoU 标签并重训回归器（一天量级），且要验证新候选分布下剪枝/并入是否仍成立。
   - **候选生成/分割新管线**：13.9% 查询池内无正确对象、oracle 单候选仅 0.71，这是选择层之上的硬上限（多天量级）。
4. 建议：锁定 C 作为论文方法版本，先做验证（多种子/更多场景不可得时可做鲁棒性分析），把上述两个方向写入 future work。
