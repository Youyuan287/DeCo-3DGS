# LERF-OVS 第 2 步：候选重排器实验报告

日期：2026-10-30
协议：leave-one-scene-out（4 折，每折 3 个场景训练、第 4 个评估）；208 条查询、1097 个候选。
标签：每个候选单独渲染得到的 IoU。
脚本：`lerf_candidate_dump.py`、`lerf_selector_experiments.py`、`lerf_rerank_gap.py`。
产物：服务器 `deco-b123/lerf_selector_20261030/`，本地 `scannet_seed1234_repro/lerf_selector_20261030/`。

## 1. 设置

- 候选 = released top-5 pool（含叶节点提升，实际平均 5.3 个候选/查询）。
- 特征（全部无 GT）：相似度分数、deficit、rank、n_cands、is_leaf、root_score、log(点数)、点数占 root 比例、叶节点数、叶增益、渲染掩码面积占比、top-1/top-2 分数差。
- 选择器：GBM 回归候选 IoU，每查询取 argmax（单候选选择）；另有 gate 变体（预测增益超过 tau 才从 rank-1 切换）和"重排后沿用 gap 规则"变体（保持多标签）。

## 2. 主结果（逐查询平均 IoU，场景平均）

| 方法 | 平均 IoU | 相对 main |
|---|---:|---:|
| DeCo main（gap 多标签） | 0.6396 | — |
| rank-1 单候选（不重排） | 0.5327 | −10.7 |
| 选择器（重排后取 argmax，单候选） | 0.5995 | −4.0 |
| 选择器 + gate | 0.5854 | −5.4 |
| **重排 + gap（多标签）** | **0.6358** | **−0.4** |
| oracle 单候选上限 | 0.7094 | +7.0 |

## 3. 结论

- **排序信号是真实的**：选择器把单候选选择从 0.5327 提到 0.5995（+6.7），说明特征能分辨"哪个候选更对"。
- **但单候选协议本身输给多标签 main**（−4.0）：DeCo 的 gap 规则选多个候选带来的收益，比排序改进还大。必须保持多标签。
- **重排 + gap 恢复多标签后仍略低于 main（−0.4）**：逐场景 1 胜 2 平 1 负（teatime +0.4，waldo 持平，ramen −1.6）。也就是说，**在 LERF 上，现有的分数/几何特征没有带来超过 DeCo main 的增益**。
- oracle 单候选 0.7094，说明候选池里的信息远没有被兑现——差距在证据层。
- 与 ScanNet 对比很有信息量：ScanNet 的选择器增益来自模式+多视角足迹证据（+1.86、准确率 +3.6pp）；LERF 这轮特征里没有这类证据，结果就停在 main 附近。**两边的一致结论：分数形状特征只能改善排序，不能改善取舍；要兑现上界必须有候选级证据。**

## 4. 下一步（LERF 方向）

1. **补证据特征**：LERF 的 V2 机器（SAS bank、observations、mode support）与 ScanNet 同构，可提取候选级模式分数/advantage/reliability 与可见性特征，重跑本实验。
2. **子集选择器**：greedy 候选组合的上界是 0.751（top-5 子集），远超任何前缀规则；用"预测 IoU 排序 + 贪心并集"替代 gap 前缀，配合证据特征才有希望。
3. 4 个场景的 LOSO 统计功效有限，结论只作方向判断，最终需要更多场景或跨数据集验证。
