# 22 — "别选空候选"的 +4.2 能不能拿到官方读端？答案：不能，能拿到的是 +1.50，而且它是修 bug 不是方法

**日期**：2026-11-04
**背景**：[21_BOUNDARY_CONTRAST_RESULT.md](21_BOUNDARY_CONTRAST_RESULT.md) 报告"46.5% 的行渲染为空，
单独修它就值 +4.2"（0.5565 → 0.5982，in-harness）。本文检验它能否翻译到官方读端。
**结论**：**不能。官方读端里 +4.2 不存在**（V1 与 baseline 逐像素完全相同）。
真正的可达效应是 **+1.50 macro**，来自 **208 个 unit 里的 5 个**，全部在 ramen，CI 勉强不含 0。

---

## 0. 先说为什么预料它会消失

诊断口径（`cnone_gate_tf`）每次**只渲染一个候选**，所以"该候选在这个视角不可见"直接等于 IoU 0，
占 46.5%。官方读端（`eval_lerf_relags.py`）渲染的是 gap 前缀的**并集**，
一个不可见的簇贡献 **0 像素**——把它删掉，输出掩膜逐像素不变。
所以 "+4.2" 里绝大部分不可能存在。

## 1. 跑法

`analysis/lerf_visibility_prefix_eval.py`，四场景 208 unit，同场（`ref/relags_hf`）同 harness。
每个 (view, prompt) 算四个变体，GT 只用于打分：

| 变体 | 规则 |
|---|---|
| base | 官方 gap 前缀，并集渲染 |
| V1 | 从前缀里删掉**本视角不可见**的候选 |
| V2 | 按 (是否可见, 相似度) 重排后**重新求 gap** |
| V3 | 若前缀在本视角渲染为空，回退到池子里**最好的可见候选** |

自检：`prefix_matches_rebuild` 在全部 unit 上为 1（我重建的前缀与官方 `search()` 返回值一致）。

## 2. 结果

**base macro = 0.6401，与官方锚点逐位一致。** ⇒ 这个 LERF-OVS 场上
（与 ScanNet 不同）磁盘产物是能复现锚点的，下面的数值是**对官方数字**的增量。

| 变体 | macro | 配对差 vs base | 改变 unit 数 |
|---|---:|---|---:|
| base | **0.6401** | — | — |
| V1 | **0.6401** | −0.0000 CI[−0.0000,+0.0000] | 5/208 |
| V2 | 0.6368 | +0.0025 CI[−0.0217,+0.0276] | 21/208 |
| **V3** | **0.6524** | **+0.0150 CI[+0.0018,+0.0314]** | **5/208** |

**V1 与 base 逐像素相同**（5 个 unit 的差为 0）→ 证实"删掉不可见候选"是空操作。
**V2 无效**（CI 跨零）→ 可见性排序不能改善 gap。

**V3 的 +1.50 全部来自 5 个 unit，且全在 ramen：**

| scene | prompt | 前缀可见数 | base | V3 |
|---|---|---:|---:|---:|
| ramen | bowl | 0 | 0.000 | 0.089 |
| ramen | bowl | 0 | 0.000 | **0.945** |
| ramen | sake cup | 0 | 0.000 | **0.945** |
| ramen | bowl | 0 | 0.000 | 0.856 |
| ramen | napkin | 0 | 0.000 | 0.277 |

per-scene：figurines 0.6329/0.6329、**ramen 0.5115/0.5609**、teatime 0.8097/0.8097、waldo 0.6062/0.6062。
**只有一个场景动，其余三个一位不变。**

## 3. 18 个"注定为 0"的 unit，拆成两类

| 类型 | n | 能否被选择规则救 |
|---|---:|---|
| 前缀在本视角全不可见，但池子里**有**可见替代 | **10** | 是（V3 救回 5 条） |
| 整个候选池在本视角都不可见 | **8** | **否**——对象在该视角根本没被表示 |

⇒ 官方读端有 **8.7%（18/208）的预测渲染为空、按定义 IoU = 0**。
其中一半是**选择缺陷**（池里有答案，gap 规则看不见可见性），另一半是**覆盖缺陷**（池里没有）。

## 4. 该怎么定性

**不是方法，是读端的 sanity guard。** 三条理由：

1. **触发率 5/208、单场景、CI 下界 +0.0018**——正好踩在本项目此前判定为噪声的形态上
   （见 `lerf-trainingfree-gatee-state` 对 "2 场景 + 3–7% 触发率" 的处置）。
   把它当贡献报，审稿人一拆就散。
2. **规则是视角相关的**：同一 prompt 在不同相机上会选出不同的 3D 区域。
   任务输出是逐视角掩膜（协议允许），但"方法"层面这是自相矛盾——
   官方方法的选择是 view-independent 的（`search()` 不吃相机参数）。
3. 它能做的只是把"必然 0"变成"可能 >0"，不改善任何本来就非空的预测（V1 = base 已证）。

**建议**：作为 pipeline 的断言保留（`if pred.sum()==0: fallback`），
在论文里如果提，只能放在实现细节/失败模式，不能进贡献列表。

## 5. 对 21 号报告的更正

- 那句"空渲染是最大的单个免费杠杆（+4.2）"**作废**：它是单候选诊断口径的伪影。
- 仍然成立的部分：`area==0` 行占 46.5%、去掉后 `ρ(area,IoU)` 从 0.637 掉到 0.282、
  J 的适用域因此排掉 53.8% 的行。这些是**诊断口径内**的事实，不影响 J 的裁决。
- 新增事实：**官方读端 8.7% 的预测渲染为空**，其中 10 条池内有可见替代。
