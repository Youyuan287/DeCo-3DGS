# 14 — 两个创新点的包装方案（含"双数据集同时有效"的诚实判定）

日期 2026-11-03。依据：E0–E16 实测 + 开源代码比对（13 号文件）。

## 0. 先回答"能不能两个点都在两个数据集上同时为正"

**目前不能，而且原因已被测出来，不是调参不够。**

| 干预类型 | LERF-OVS | ScanNet-10 | 依据 |
|---|---:|---:|---|
| 特征级均值融合（E0） | 0.6383（−0.32） | +2.79~+3.18 | 实测 |
| 判决级融合（逐视角投票） | 0.4692（单候选） | 28.65 vs 均值 29.14 | E16 |
| 行轴偏置 `a_g` | +0.97 | **恒等（引理）** | E3/E4 |
| 列轴偏置 `zR` | **恒等（引理）** | **+5.62** | E12 |
| 集合级证书 | **+3.13** | 失败（粒度） | E5 |

两个数据集的**信息分布是相反的**：
- ScanNet：逐视角特征弱（投票 28.65，均值 29.14，两者 90% 一致），融合成单特征后强（released 50.15）；
- LERF：逐视角证据强（当评分器命中 65.3%），融合成单特征后弱（一致性 13.7%）。

这不是实现问题——`cos(NAG 根特征, 观测均值特征) = 0.959~0.993`，两者同一空间。
**是任务本身让"该在哪个轴融合"不同。**

因此"两个创新点都同时提升两个数据集"在现有场上不可达。要么接受下面的包装，
要么投入重编码（S0）去改变 ScanNet 的逐视角特征质量——成本高、收益未知。

## 1. 推荐包装：一个原则，两个实例，两处可证明的零结果

### 创新点 A：Marginalization-Correct Calibration（决策轴校正）

**What**：开放词汇 3D 的分数张量 `S[v,g,c]` 带三类与查询无关的加性项（视角、区域、类别）。
**现有方法的关键缺陷**：把"校准"当作通用操作——zR、C1、原型校准都默认"校准总是有用"。

**我们的原则**：
> 决策只在它**没有**边缘化的轴上受限；作用于被边缘化轴的校正，数学上是恒等变换。

**可证明的两个推论**（本仓库已实现验证）：
- `argmax_c (S[g,c] − a_g) = argmax_c S[g,c]`（行常数不改 argmax）→ 区域轴校正在 ScanNet 上必然无效；
- `top-k_g (S[g,c] − b_c) = top-k_g S[g,c]`（列常数不改排序）→ 类别轴校正在 LERF 上必然无效。

**效果**：ScanNet `raw 40.36 → zR 45.98 → zR+E0 48.77`（+8.41）；LERF 上**证明性零结果**。

**新颖性定位**（对照已发表工作）：
| 工作 | 它做的 | 我们的差别 |
|---|---|---|
| PTC 2608.03991 | 用视觉原型校准文本嵌入（2D） | 它不问"该不该校准"；我们给出**何时必然无效**的判据 |
| Target-Aware 2610.21619 | 文本注入 + 公共成分 | 同族；我们把它归入列轴，并证明行轴不可辨识 |
| zR / C1（我们自己的） | 单一校正 | 我们把它变成"按决策轴选择"的规则 |

**风险**：机制本身仍是校准，审稿人可能说"这是 zR 加个定理"。

### 创新点 B：Certified Decision Revision（判决证书）

**What**：不改分数，只在**同一批证人**上做**配对**比较，用**半样本多数**决定是否改判。
**现有方法的关键缺陷**：默认"改进 = 重打分"。但 E14/E16 显示所有重打分与融合算子都失败。

**我们的原则**：
> 当逐视角证据好、但单特征坏时（LERF），正确的干预不是融合证据，而是**用证据去审计现有判决**。

**效果**：LERF `0.6401 → 0.6711`（+3.13，CI [+0.0114,+0.0548]），deep 族 0.2914→0.6515，
19/208 触发；按 5 帧视角簇重采样仍 0.6711（排除伪重复）。

**ScanNet 上的零结果（实测，非不知）**：逐视角投票 28.65 vs 特征均值 29.14，一致率 90%
→ 决策级融合在 ScanNet 上无增量；证书依赖的"逐视角证据更好"前提在 ScanNet **不成立**。

**新颖性定位**：与 QAGaussian（学习式粒度路由）、DIGS（实例发现）、SCI-CLIP（2D 区域图）都不同；
与稳定性选择（Meinshausen–Bühlmann）同源但用于**成对集合改判**而非变量选择。

## 2. 为什么这不是"两个模块拼装"

一条原则（轴边缘化）推出两个实例：
- 轴 A 上受限 → 只能做**分数**校正（列轴）；
- 轴 B 上受限 → 只能做**判决**校正（视角轴，且必须是集合级）。

删掉任一点，另一点的核心问题（"为什么在这里有效、在那里必然无效"）就答不出来。

## 4. 还差什么才能称为"有效"

| 缺口 | 代价 | 决定什么 |
|---|---|---|
| ScanNet 上加 `σ(opacity)<0.1` 重跑三行 | 10 分钟 | 能否与 OpenGaussian 同表（13 号文件） |
| 与 CSLS/hubness 的受控对比 | 半天 | 创新点 A 是否被先行覆盖 |
| 未参与设计的场景复现（3D-OVS） | 2–4 小时 | 创新点 B 是否只是 LERF 特例 |
| 若坚持"双数据集都为正"：重编码 ScanNet 逐视角特征（S0） | 1–2 天 | 整个包装是否要重写 |

## 5. 我的判断

- 按上面的包装，故事是完整且诚实的，**但两个点各自只在一个数据集上为正**，这是最大风险；
- 想在两个数据集上同时为正，唯一有依据的路径是 **S0（重编码）**，把 ScanNet 的逐视角特征做
  到 LERF 的水平；在此之前，任何"两个点都双数据集有效"的说法都没有实验支撑；
- 我不建议为了满足形式要求去构造第二个"有效"，那会在 rebuttal 阶段崩掉。

## 6. E16 决定性结果（写完立刻跑）

同一场景、同一文本库，把逐视角**判决**（每视角 argmax 投票）与逐视角**特征**（均值）分别与 zR 融合：

| 算子 | scene0000 mIoU |
|---|---:|
| released + zR | 50.15 |
| **zR + 特征均值证据（E0）** | **51.98** |
| **zR + 逐视角投票（判决级）** | **39.22** |
| 投票单独 | 28.65 |
| 特征均值单独 | 29.14 |
| 投票与均值一致率 | 90.0% |

**10 场景完整结果（macro mIoU）**

| 算子 | macro |
|---|---:|
| 逐视角投票（判决级，单独） | 29.04 |
| 逐视角特征均值（特征级，单独） | 26.86 |
| released + zR | 45.98 |
| **zR + 特征均值** | **47.97** |
| **zR + 逐视角投票** | **41.12** |
| 投票与均值一致率 | 87.9% |

逐场景 `zR+vote − zR+mean` 在 10/10 上为负（最大 −15.5，最小 −0.6）。

**结论：在 ScanNet 上，判决级融合比特征级差 6.9 分，且逐场景无一例外。**
决策级路线在 ScanNet **不是调不出来，是方向相反**。

## 7. 由此得到唯一站得住的"统一原则"

两个数据集不是"谁的方法更好"，而是**逐视角证据与合并特征的相对可靠性相反**：

| | 逐视角证据 | 合并特征 | 该用哪一级 |
|---|---|---|---|
| LERF | 强（当评分器命中 65.3%） | 弱（一致性 13.7%） | **判决级** |
| ScanNet | 弱（投票 28.65） | 强（released 50.15） | **特征级** |

于是论文的统一原则可以写成：

> **融合层级不是超参数，而是由"逐视角证据相对合并特征的可靠性"决定的可测量决策。
> 可靠时融合判决，不可靠时融合特征。**

这条原则的价值：
- 它同时解释两个数据集，且**用同一个算法**（先测量、再分支），不是两套模块；
- 它解释了为什么所有"只做一种融合"的方法必然在一个数据集上失败（VCLS、局部对比、E0、投票都是）；
- 它给出可测的判据（可用**视角二分自一致性**估计，不需要 GT）。

**尚未验证的部分（必须说清）**：这个"可靠性判据"本身还没有实现和检验。
若它不能仅凭观测（无 GT）分辨两种情形，那么论文只能退回"两个实例 + 两个可证明的零结果"，
统一性会弱一档。
